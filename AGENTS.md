# ESCTRIX Quantum — Antigravity Agent Guidelines & Repository Memory

This document provides localized architecture knowledge, patterns, and development guidelines for Antigravity AI assistants working on the **ESCTRIX Quantum** repository.

---

## 1. Project Overview & Core Mission
**ESCTRIX Quantum** is a decentralized, zero-knowledge, end-to-end encrypted (E2EE) messaging, calling, and file transfer platform. It combines direct peer-to-peer WebRTC mesh channels with lightweight WebSocket signaling and persistent cloud storage.

---

## 2. Technical Stack
- **Backend**: Python 3.11, FastAPI, Uvicorn, WebSockets, `psycopg2-binary`, `bcrypt`, `qrcode`, `pillow`.
- **Database Engine (Dual-Mode)**:
  - **Cloud / Render**: Supabase PostgreSQL connection pool via `SUPABASE_DB_URL` or `DATABASE_URL`.
  - **Local Development**: SQLite (`users.db` / `DB_PATH`) fallback when cloud credentials are not supplied.
  - **Account Protection**: Auto-pruning is disabled by default (`ENABLE_ACCOUNT_PRUNING=false`) to ensure accounts and login credentials persist permanently across server restarts and container spin-downs.
- **Frontend**: Vanilla HTML5, modern CSS3 (glassmorphic dark cyber aesthetic), native Vanilla JavaScript (ES2022+), WebRTC (`RTCPeerConnection`, `RTCDataChannel`, `RTCRtpSender`).
- **Cryptographic Model**: Zero-knowledge encryption. Payloads and media are encrypted/decrypted client-side. The server acts as a zero-knowledge relay and encrypted vault.

## 3. Architecture Rules & Coding Standards

### A. WebRTC Calling Engine
1. **Camera Flipping**:
   - Never renegotiate or re-initiate calls (`this.initiate('video')`) to switch cameras.
   - Use `navigator.mediaDevices.getUserMedia({ video: { facingMode: mode }, audio: false })` to acquire the new video track.
   - Use `RTCRtpSender.replaceTrack(newVideoTrack)` on all active peer connections (`s.directCallPC` and mesh peers in `s.p2p.peers`).
   - Stop previous video tracks cleanly.
2. **Call Termination & Teardown**:
   - Calling signals: `call_request`, `call_accepted`, `call_declined`, `call_ended` (for Space rooms), and `direct_call_offer`, `direct_call_answer`, `direct_ice_candidate`, `direct_call_declined`, `direct_call_end` (for 1-on-1 direct calls).
   - `this.call.end(sendSignal = true)`: When a call end signal is *received* from a remote peer, call `end(false)` so termination signals are not echoed in an infinite loop.
   - Always stop local media streams, screen-share tracks, remote video DOM elements, and timer intervals upon teardown.

### B. E2EE Chunked Media Transfer
- Multi-megabyte files (videos, PDFs, images) are sliced into 64KB binary/JSON chunks (`CHUNK_SIZE = 64 * 1024`).
- P2P Space rooms use `RTCDataChannel` with backpressure control (`dc.bufferedAmount` threshold).
- Direct 1-on-1 chats use WebSocket relay (`direct_file_meta`, `direct_file_chunk`, `direct_file_ack`, `direct_file_complete`).
- In-chat video playback uses glassmorphic video bubbles (`msg.type === 'video'`) with duration, download buttons, and lightbox viewers.

### C. Ephemeral Vanishing & View-Once Media
- Vanish modes: `Off`, `5s`, `10s`, `30s`, and `View-Once (1-View 🔒)`.
- View-Once media displays encrypted blurred cards that decrypt once upon click and permanently self-destruct from DOM and memory upon close.

### D. Biometric Passkeys (FIDO2 / WebAuthn)
- Allows users to register hardware authenticators (FaceID, TouchID, Windows Hello).
- Passkey challenges generated by `/api/auth/passkey/challenge` and credentials saved in `passkey_credentials` table.

## 4. Database Schema Reference (Supabase PostgreSQL / SQLite)
- `users`: Permanent user profiles, credentials (`password_hash`), `account_id`, `avatar_color`, `avatar_photo`, `role`, `created_at`, `last_login_at`.
- `contacts`: Mutual and added friendships (`owner_username`, `contact_account_id`, `contact_username`, `contact_name`, `status`).
- `offline_messages`: Queued encrypted messages for offline peers.
- `saved_messages`: Encrypted personal cloud vault notes.
- `direct_messages`: 1-on-1 chat history with vanish flags and read receipts.
- `passkey_credentials`: Biometric public keys (`credential_id`, `public_key`, `sign_count`).
