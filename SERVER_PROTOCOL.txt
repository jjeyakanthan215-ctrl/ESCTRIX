================================================================================
              CIPHER6 (HEXACONNECT) — SERVER PROTOCOL SPECIFICATION
================================================================================

Server Type:      WebSocket (AsyncIO)
Address:          0.0.0.0:8765
Connection Map:   {username: websocket} in-memory dictionary
Auth:             JWT tokens (issued on login, validated on every message)
Heartbeat:        Ping every 30 seconds, update last_seen, remove dead connections
Rate Limiting:    Per-IP based

================================================================================
  RATE LIMITS
================================================================================

Action                  Limit
---------------------   -------------------------
Registrations           5 per hour per IP
Login attempts          5 per 5 minutes per username
Messages                30 per minute per user
Search queries          10 per minute per user
Friend requests         20 per hour per user

================================================================================
  MESSAGE FORMAT
================================================================================

All messages are JSON objects with this structure:

{
    "type": "MESSAGE_TYPE",
    "token": "jwt_token_here",     (required for all except REGISTER and LOGIN)
    "data": { ... }                (type-specific payload)
}

Server responses:

{
    "type": "RESPONSE_TYPE",
    "success": true/false,
    "data": { ... },               (on success)
    "error": "error message"       (on failure)
}

================================================================================
  AUTHENTICATION MESSAGES
================================================================================

--- REGISTER ---
Client → Server:
{
    "type": "REGISTER",
    "data": {
        "username": "darkphoenix",
        "display_name": "Alex Chen",
        "password": "securepassword123"
    }
}

Server → Client (success):
{
    "type": "REGISTER_RESPONSE",
    "success": true,
    "data": {
        "token": "eyJhbGciOiJIUzI1NiIs...",
        "user": {
            "id": 1,
            "username": "darkphoenix",
            "display_name": "Alex Chen",
            "bio": "",
            "avatar_index": 0,
            "created_at": "2026-08-06T12:00:00"
        }
    }
}

Server → Client (failure):
{
    "type": "REGISTER_RESPONSE",
    "success": false,
    "error": "Username 'darkphoenix' is already taken"
}

Validation errors:
  - "Username must be 3-20 characters"
  - "Username can only contain lowercase letters, numbers, and underscores"
  - "Username 'admin' is reserved"
  - "Password must be at least 8 characters"

================================================================================
  CALLING MESSAGES
================================================================================

SECURITY: Server checks are_friends() before relaying any call message.
          If not mutual friends, returns error.

--- CALL_REQUEST ---
Client → Server:
{
    "type": "CALL_REQUEST",
    "token": "jwt...",
    "data": {
        "target_username": "alice"
    }
}

Server checks:
  1. Are they mutual friends? → if no, error "You can only call friends"
  2. Is target online? → if no, error "User is offline"
  3. Is target in a call? → if yes, return BUSY

Server → Target:
{
    "type": "INCOMING_CALL",
    "data": {
        "caller_username": "darkphoenix",
        "caller_display_name": "Alex Chen"
    }
}

================================================================================
  CHAT MESSAGES
================================================================================

--- CHAT_MESSAGE ---
Client → Server:
{
    "type": "CHAT_MESSAGE",
    "token": "jwt...",
    "data": {
        "target_username": "alice",
        "encrypted_content": "base64(IV || ciphertext || authTag)"
    }
}

Server checks:
  1. Are they mutual friends? → if no, error
  2. Is target online?
      YES → relay directly to target via WebSocket
      NO  → store in pending_messages table

Server → Target (if online):
{
    "type": "CHAT_MESSAGE",
    "data": {
        "from_username": "darkphoenix",
        "encrypted_content": "base64(IV || ciphertext || authTag)",
        "timestamp": "2026-08-06T12:45:00"
    }
}

(If target is offline, message is stored and delivered on next login)

================================================================================
  CONNECTION LIFECYCLE
================================================================================

1. Client connects to WebSocket
2. Client sends LOGIN or REGISTER
3. Server validates → adds to connection map {username: websocket}
4. Server notifies all online friends: FRIEND_STATUS (is_online: true)
5. Server sends pending friend requests + pending messages
6. Heartbeat ping every 30 seconds
7. On disconnect:
   - Remove from connection map
   - Update last_seen in database
   - Notify online friends: FRIEND_STATUS (is_online: false)
   - If in a call: send HANG_UP to peer

================================================================================
  SECURITY RULES (Server Enforced)
================================================================================

1. All messages (except REGISTER/LOGIN) require valid JWT token
2. CALL_REQUEST requires mutual friendship (status = 'accepted')
3. CHAT_MESSAGE requires mutual friendship (status = 'accepted')
4. Users cannot send friend requests to themselves
5. Duplicate friend requests are rejected
6. Rate limiting on all endpoints
7. Login throttling: 5 failures = 5 min lockout
8. Username validation on registration
9. JWT expiry: 7 days (configurable)
10. Passwords never logged or stored in plaintext
